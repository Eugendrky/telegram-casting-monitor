# telegram-casting-monitor

Telegram-сервис поиска кастингов в группах и каналах, доступных вашему аккаунту. Работает внутри Telegram, без сайта и отдельного приложения: **Telethon** читает источники через авторизованный аккаунт, а бот, созданный через **BotFather**, позволяет управлять поиском и получать результаты в личном чате.

## Что делает

1. Раз в `SCAN_INTERVAL_MINUTES` читает недавние сообщения в доступных группах и каналах (время и число сообщений настраиваются).
2. Находит объявления о кастингах и отбирает их по городу, полу, возрасту, росту и стоп-словам.
3. Запоминает просмотренные сообщения в SQLite, чтобы не присылать дубли. Найденные кастинги помечает после успешной отправки.
4. Отправляет уведомления в личный чат с BotFather-ботом, если указан `BOT_TOKEN`. Без токена использует прежний режим отправки в «Избранное».

### Управление прямо в Telegram

- `/start`: меню бота;
- `/sources`: группы и каналы аккаунта с выбором и постраничным просмотром (8 на страницу);
- `/scan`: запрос внеочередной проверки;
- `/status`: число проверок и найденных кастингов;
- `/settings`: просмотр критериев поиска, которые пока задаются в Railway.

В меню **Источники** нажимайте на название группы или канала. Первый выбор переводит поиск в режим **Только выбранные**. Можно включить **Все источники** и затем вернуться к сохранённому списку. Если включить режим «Только выбранные» без выбранных источников, сканирование ничего не отправляет. При перезапуске Railway выбранные источники сохраняются в SQLite (при подключённом постоянном томе).

Список доступных групп читается из авторизованного обычного Telegram-аккаунта. Бот BotFather сам по себе не может читать все ваши группы, поэтому обязательно нужна Telethon-сессия. Меню и уведомления доступны только владельцу аккаунта или пользователю с `BOT_OWNER_ID`.

## Начальная настройка

1. На [my.telegram.org/apps](https://my.telegram.org/apps) получите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` для обычного аккаунта Telegram.
2. Локально запустите `python3 -m venv .venv`, `source .venv/bin/activate`, `pip install -r requirements.txt`, затем `cp .env.example .env` и заполните API-ключи. Получите сессию командой `python scripts/login.py`.
3. Создайте Telegram-бота в [@BotFather](https://t.me/BotFather), скопируйте токен в секретную переменную `BOT_TOKEN`. Не публикуйте токен или сессию в GitHub.
4. Разверните репозиторий на Railway с переменными `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`, `BOT_TOKEN` и профилем (`PROFILE_CITY`, `PROFILE_GENDER`, `PROFILE_AGE` и др.). `BOT_OWNER_ID` необязателен; по умолчанию доступ имеет только пользователь сессии.
5. Прикрепите постоянный Railway volume в `/data` и задайте `SQLITE_PATH=/data/seen.db`, чтобы настройки и история сообщений сохранялись при перезапуске. Сервис отвечает на HTTP health-check через `PORT`.
6. **Откройте созданного бота в Telegram и нажмите Start**, иначе Telegram не разрешит боту начать переписку с вами.

### Проверка

```bash
python -m unittest discover -s tests
python -m app.main
```

### Параметры

В `.env.example` показан полный список переменных. `SCAN_MODE=all` проверяет доступные группы и каналы, `SCAN_MODE=title` проверяет только группы с тематическими названиями. Ручной выбор в `/sources` имеет приоритет перед `SCAN_MODE`. Интервал сканирования и лимиты запросов не стоит устанавливать слишком агрессивно, чтобы не получать FloodWait.

**Безопасность:** храните `TELEGRAM_SESSION` и `BOT_TOKEN` только в секретных переменных и не делитесь ими. Аккаунт может читать только группы и каналы, в которые он уже вступил. Не запускайте несколько экземпляров сканера с одной сессией и базой без отдельной настройки.
