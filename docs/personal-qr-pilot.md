# Telegram QR: пилот в одном боте

**Статус:** код в экспериментальной ветке. Не развёрнут в Railway и не проверен с настоящим Telegram-аккаунтом. Подключение к трём группам пока не подтверждено.

## Назначение

Рабочий Telegram-бот обслуживает пользователей через Bot API. В качестве эксперимента владелец может явно подключить собственный аккаунт через официальный Telegram API и QR. Только после авторизации разрешено прочитать три выбранных и одобренных публичных источника.

Сервер не читает диалоги аккаунта и не вступает автоматически в группы. Для каждого пользователя хранится отдельная зашифрованная сессия, список источников, архив сообщений и статусы доставки. Пока включён **только пилот владельца**.

## Параметры для безопасного включения

Создать приложение на официальном https://my.telegram.org и получить свои `api_id` и `api_hash`. Это ключи приложения, их не нужно отправлять в чат с ИИ. При необходимости Telegram может ограничивать их получение.

В **настройках Railway**, не в GitHub, задать:

- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`: ключи Telegram-приложения.
- `SESSION_ENCRYPTION_KEY`: случайный 32-байтный ключ Fernet в base64 URL-safe формате, созданный в защищённой среде.
- `PERSONAL_QR_ENABLED=true`: пилот включён только после явного разрешения.
- `BOT_OWNER_ID`, `BOT_TOKEN`: уже заданы. **Не менять** существующий токен.
- `SQLITE_PATH=/data/castings.db`: сохраняется на постоянном томе.

Не задавать ключ сессии заново после первого подключения: без него расшифровка прежних сессий невозможна. Не публиковать токены, QR, значения переменных и пользовательскую историю в GitHub или логи.

## Команды владельца в том же Telegram-боте

- `/connect`: одноразовый QR-код для авторизации. Сканируется в Telegram → Настройки → Устройства. Подтверждается, что вошедший аккаунт соответствует `BOT_OWNER_ID`.
- `/account`: состояние подключения.
- `/addmine @moscowfilms`, `/addmine @kinocekh`, `/addmine @castingiot4000r`: выбрать три заранее одобренных источника.
- `/mymine`: посмотреть выбранные.
- `/scanmine`: ограниченная проверка по расписанию (30 минут между успешными запусками).
- `/mycastings`: последние доставленные персональные объявления.
- `/disconnect`: запрос подтверждения удаления и отзыва сессии.
- `/guardian`, `/ready`: состояние сервера и публичных источников.

Объявления доставляются **в личный чат с тем же ботом**, группа-приёмник не нужна.

## Ограничения пилота

- Вход с облачным паролем (2FA) не поддержан: бот просит не отправлять пароль, вход прекращается.
- На источнике прочитывается не более 80 последних сообщений за запрос, новыми считаются только сообщения за последние 48 часов. Это не гарантия полного охвата при высоком потоке.
- В случае FLOOD_WAIT сканирование останавливается и на источник ставится отложенный повтор.
- Новые объявления других аккаунтов не допускаются в общий архив. Поиск пользовательских сессий не включён для всех пользователей.
- Автоматические проверки подтверждают структуру и безопасность кода, **реальные чтение и доставку** можно подтвердить только после ручной авторизации и отдельного испытания.

## План приёмки

1. CI, база, тесты разделения пользователей и зашифрованного хранения.
2. Проверка на отдельном окружении Railway или резервной копии постоянного тома.
3. Подключение официальных API-ключей и безопасное хранение ключа шифрования.
4. Пилот /connect на аккаунте владельца; /account показывает подключён.
5. Один разрешённый источник; /scanmine; подтверждение времени, идентификатора сообщения, исходной ссылки и реальной доставки.
6. Остановка, отзыв сессии и отсутствие повторной доставки.
7. После этого остальные два источника и тест перезапуска, затем решение о включении для остальных пользователей.
