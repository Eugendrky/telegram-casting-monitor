# Junction Bot: экспериментальная интеграция

Статус: **интеграционный код добавлен, независимые тесты проверяют логику, реальный поток через Junction пока не подтверждён**.

## Схема

Junction Bot читает согласованные публичные источники, пересылает новые объявления в **отдельную Telegram-группу-приёмник**, к которой подключён наш бот. Рабочий бот принимает сообщения только от явно привязанного Telegram ID отправителя и только из привязанной группы. Оригинальный канал должен быть подтверждён ссылкой вида `https://t.me/username/123` в тексте или полем `forward_origin`, иначе публикация отклоняется. Фильтрация, запись, дедупликация и уведомления используются из существующей системы.

**Ограничение:** ссылка в тексте является утверждением отправителя, а не криптографическим доказательством происхождения. Настройка источника на стороне Junction и проверка реально полученных сообщений обязательны.

## Подготовка для владельца

1. В Junction Bot проверить, получает ли сервис сообщения из **одного** публичного источника `@moscowfilms` без Telegram-сессии пользователя. Выбрать доступный пробный режим; условия и лимиты уточнить в интерфейсе самого Junction.
2. Создать закрытую группу Telegram, например «Casting Relay Test»; добавить только наш бот и Junction Bot. Не добавлять пользователей-подписчиков. Убедиться в настройках BotFather, что наш бот может получать сообщения **от других ботов в группах** (зависит от доступной версии Telegram; если настройка недоступна, эта схема не функционирует).
3. Добавить Junction Bot администратором группы только с правом публиковать сообщения. Остальные права не нужны. В Junction настроить источник `@moscowfilms` и группу-приёмник, **включить исходные ссылки**.
4. Дождаться первого сообщения Junction в группе. Владелец (ID из `BOT_OWNER_ID`) **отвечает на сообщение Junction**: `/junction_bind @moscowfilms`. Бот проверяет ID отправителя из ответа и связывает группу с одним уже одобренным источником.
5. Убедиться, что поступило объявление с ссылкой `t.me/moscowfilms/номер` или с корректным `forward_origin`, и что оно дошло подписчику. Повтор исходного сообщения не должен отправляться снова.
6. Отключение: `/junction_unbind` в группе, только от владельца. Для прекращения обработки самого источника: `/disable <код источника>` в личном чате администратора.

## Необходимые реальные проверки

- Сохраняет ли Junction ссылку на первоначальную публикацию и текст.
- Поступает ли сообщение от Junction через Bot API к нашему боту; некоторые ограничения Telegram могут блокировать доставку сообщений одного бота другому.
- Не является ли объявление защищённым/не предназначенным для републикации.
- Пропущенные, удалённые, отредактированные сообщения; сохранение курсоров и ограничения Junction.
- Нет ли совпадения с источником, который открыт в веб-сканере. Первоначальная доставка из веб-сканера обычно недоступна для этих групп, но общая дедупликация должна защитить пользователя.
- Не требуется ли дополнительная настройка входящего сообщения, например отдельный бот-аккаунт для пересылки.

## Важные ограничения

Это **не автоматическое создание подписки в Junction**. Без ручной настройки собственного аккаунта Junction и группы-приёмника код будет бездействовать. Не требуется загружать Telegram-сессию в Railway. До реальной проверки не заявлять, что чтение трёх исходных групп работает. Запрещённые/частные источники не подключать.
