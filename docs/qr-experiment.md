# Изолированный опыт: Telegram Web QR

Это отдельный сервис авторизации Telegram Web. Он **никогда не считывает группы и не отправляет кастинги**. Нужен отдельный бот, созданный через @BotFather: использовать BOT_TOKEN действующего бота нельзя, иначе два процесса будут конфликтовать при getUpdates.

Railway: создать отдельный сервис из этой ветки, выбрать Dockerfile `Dockerfile.qr`, подключить постоянный том `/data`. Переменные сервиса: `LOGIN_BOT_TOKEN`, `LOGIN_OWNER_ID`, `LOGIN_PROFILE_DIR=/data/telegram-web`.

Сначала в отдельном боте: `/start`, `/qr`, затем на телефоне Telegram → Настройки → Устройства → Подключить устройство. После сканирования: `/status`.

**Не отправлять** пароль, QR или экспорт Telegram-сессии в ChatGPT. QR приходит только владельцу из отдельного бота. Если Telegram требует облачный пароль, прототип прекращает авторизацию; нельзя передавать пароль через бота.

Уязвимости и ограничения: Telegram Web может менять интерфейс; требуется авторизация личного аккаунта на сервере, что несёт риск компрометации и санкций Telegram; возможность отзыва сессии должна быть проверена в Telegram → Настройки → Устройства. Никакой доступ к чужим группам пока не доказан. Вход по QR не означает разрешения сканировать группы. Для любых реальных данных необходим отдельный этап оценки прав, ограничений и согласия.

См. независимый аудит в ветке `audit/telegram-source-review-2026-10-31`.
