# Telegram Web: доступ пользователей по списку

Telegram Web подключается отдельно для каждого разрешённого пользователя. Бот
не просит API ID/Hash и не принимает пароль Telegram в чате. QR и облачный пароль
используются только на HTTPS-странице сервиса.

## Доступ и подключение

- Владелец добавляет Telegram username командой `/weballow @username`, смотрит
  список через `/weballowed`, отзывает доступ через `/webdeny @username`.
- При первом `/webconnect` разрешённый username привязывается к неизменяемому
  Telegram ID. Владелец бота проходит проверку автоматически.
- Пользователь отдельно подтверждает подключение. Ему доступны `/webqr`,
  `/webauth`, `/webstatus`, `/websource`, `/websources`, `/webscan`,
  `/webcastings` и `/webdisconnect`.
- Вход разрешён только если Telegram ID аккаунта в Web K совпадает с ID человека,
  который открыл команду в личном чате с ботом.

## Обработка и хранение

Каждый пользователь получает отдельный профиль Chromium и отдельную очередь
доставки. Профили размещаются на томе Railway под `/data`; профиль владельца
сохраняет прежний путь `/data/telegram-web-owner`, профили остальных пользователей
разделены по Telegram ID. На одном экземпляре разрешено не более пяти активных
профилей по умолчанию; предел меняется переменной `WEB_QR_MAX_USERS`.

Обрабатываются только разрешённые администрацией и выбранные пользователем
источники. Личные переписки не запрашиваются. Сообщения выбранных источников,
курсор и результат доставки хранятся до `/webdisconnect`. Эта команда удаляет
профиль и данные сборщика; пользователь также должен завершить серверный сеанс
в Telegram → Настройки → Устройства.

Ограничения по источникам, свежести и частоте описаны в
[`cloud-web-reader.md`](cloud-web-reader.md). Внутренний интерфейс Telegram Web
не документирован и может измениться без предупреждения.
