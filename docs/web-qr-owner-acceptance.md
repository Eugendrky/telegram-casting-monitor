# Telegram Web QR: пилот владельца

Техническое решение: [ADR-0001](https://github.com/Eugendrky/telegram-casting-monitor/blob/main/docs/decisions/ADR-0001-telegram-web-no-api-credentials.md). **Не требовать от пользователя API ID / API Hash**, не предлагать Junction.

## Что реализовано в этой ветке

- `Dockerfile.webpilot`: Chromium/Playwright для Telegram Web K.
- `app/owner_web_pilot.py`: QR, проверка идентичности Telegram ID, ручное сканирование, фоновая проверка, отключение.
- `app/web_owner_store.py`: только личные сообщения владельца, независимые курсоры и очередь доставки с дедупликацией.
- `app/cloud_web_reader.py`: сканирование возможно только при совпадении аккаунта Telegram Web с `BOT_OWNER_ID`; только вручную включённые разрешённые источники.
- Рабочий бот принимает команды только от владельца и только в личном чате.

## Состояние

**GitHub CI подтверждает синтаксис и тесты кода. Реальный браузерный QR, Telegram Web, три источника и доставка из них в Telegram пока не испытаны.** Работающий сервис Railway не переключён. Приложение Telegram Web может поменять HTML и недокументированные методы без уведомления.

## Порядок отдельного испытания

1. Использовать изолированный тестовый Railway-сервис или безопасный резервный план миграции существующего сервиса. Нельзя запускать два экземпляра Bot API polling с одним и тем же `BOT_TOKEN`.
2. Подключить постоянный том `/data`, выбрать `Dockerfile.webpilot` как build Dockerfile, а стартовую команду `python -m app.bot_runtime`.
3. Установить **только** `WEB_QR_PILOT_ENABLED=true`. `BOT_TOKEN`, `BOT_OWNER_ID`, `SQLITE_PATH` сохраняются из действующего сервиса. `CLIENT_SCAN_ENABLED` должен оставаться false.
4. Проверить на сервере успешный запуск Chromium и доступность Telegram Web K **до выдачи QR**. Не публиковать порты браузера и его профиль.
5. В существующем боте владелец отправляет `/webconnect`, подтверждает риск подключения полного Telegram-аккаунта, затем `/webqr`. QR нельзя пересылать.
6. Сканирует QR через Telegram → Настройки → Устройства → Подключить устройство. Если требуется облачный пароль, отправляет `/webauth` и вводит его на HTTPS-странице своего сервиса. Не присылает пароль боту или помощнику. Ссылка действует 5 минут и разрешает одну отправку; новая ссылка отменяет предыдущую. До пяти ссылок за 10 минут. Пароль не записывается в базу или журналы приложения. Сервер и Telegram Web обрабатывают его в памяти для входа.
7. В боте `/webstatus` должен подтвердить, что Telegram ID из Web K **строго совпал** с `BOT_OWNER_ID`. Если нет, сканирование заблокировано.
8. Выбрать **один** источник: `/websource @moscowfilms`, далее `/webscan`. Сверить текст, оригинальный ID, время и ссылку. После этого по одному проверять `@kinocekh` и `@castingiot4000r`.
9. `/websources` показывает разрешённые источники, `/webcastings` показывает доставленные кастинги; `/webdisconnect` с подтверждением удаляет локальные данные и профиль браузера. **Дополнительно** завершить сеанс в настройках Telegram → Устройства.

## Ограничения и контроль

- Начальный просмотр ограничен последними 48 часами и **40 последними сообщениями группы** на запрос. Это не гарантия всей истории.
- Частота повторной проверки: минимум 30 минут на источник, ошибки откладываются на час, FLOOD_WAIT прекращает цикл на сутки.
- Объявления личного аккаунта владельца не попадают в общий архив и не рассылаются другим подписчикам.
- Статус `sending` сохраняется до ответа Telegram, чтобы после аварийной перезагрузки не произвести гарантированный повтор; такие элементы требуют ручной диагностики.
- Возможность чтения групп, изменчивость Telegram Web, правила платформы и безопасность полноценной авторизации подлежат отдельному практическому испытанию.
- Первый выпуск выполняется как явно запрошенный владельцем пилот: после CI и браузерных проверок, с тем же ботом, базой и томом. Не запускать второй polling. Реальная авторизация и чтение источников остаются отдельным пользовательским испытанием.

## Защищённая страница пароля

`WEB_AUTH_BASE_URL` задаётся точным HTTPS-origin действующего сервиса,
`WEB_QR_PILOT_ENABLED=true`, `CLIENT_SCAN_ENABLED=false`.
Страница слушает Railway `PORT`, проверка запуска: `/healthz`.
Для образа требуется `Dockerfile.webpilot`. Ключи Telegram API не нужны.

`/webauth` доступна только владельцу в личном чате после согласия и появления
запроса облачного пароля. Секрет ссылки передаётся во фрагменте URL, удаляется из
адресной строки страницей и отправляется в заголовке запроса. На сервере хранится
только его хеш в памяти. Проверяются HTTPS-origin, срок, одноразовость, согласие,
официальный адрес Telegram Web и точный Telegram ID после входа.
Внешних ресурсов и записи запросов нет. `/webdisconnect` отзывает ссылки и
удаляет профиль; Telegram-сеанс дополнительно завершается через «Устройства».

Сохранённый профиль восстанавливается при запуске только при наличии согласия.
Реальное сохранение Telegram-сеанса требует проверки после входа владельца;
браузерные тесты проверяют сохранность профиля на искусственных данных.

Откат выпуска: вернуть предыдущую ветку и `Dockerfile`, выключить
`WEB_QR_PILOT_ENABLED`. Том `/data` и SQLite не удалять. После реального входа
сначала отозвать Telegram-сеанс и выполнить `/webdisconnect`.
