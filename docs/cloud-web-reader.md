# Облачный сборщик Telegram Web

Сборщик работает в отдельном браузерном профиле каждого разрешённого
пользователя. Вход проходит через официальный Telegram Web K, без собственных
Telegram API ID/Hash. До сканирования сервис проверяет, что ID авторизованного
аккаунта совпадает с Telegram ID пользователя в личном чате бота.

Владелец вручную ведёт список доступа: `/weballow @username`, `/webdeny
@username`, `/weballowed`. Username связывается с Telegram ID при первой попытке
подключения. Дополнительно каждый пользователь подтверждает согласие в боте.
Сборщик читает только выбранные разрешённые источники и не запрашивает личные
переписки. Автоматическое вступление в группы не выполняется.

QR и ссылка двухэтапной проверки короткоживущие и привязаны к аккаунту
пользователя. Пароль вводится на HTTPS-странице, передаётся в официальный
Telegram Web и не сохраняется в базе или журналах. Профиль Chromium, объявления
из выбранных источников, курсоры и доставки хранятся на постоянном томе Railway
до `/webdisconnect`. После него пользователь также завершает серверное устройство
в Telegram → Настройки → Устройства.

Один экземпляр обслуживает до пяти активных профилей по умолчанию;
`WEB_QR_MAX_USERS` можно настроить от 1 до 20. Профили размещаются в `/data`,
отдельно по Telegram ID; профиль владельца сохраняет старый путь. Не публиковать
профили Chromium и не пересылать QR, одноразовые ссылки или облачный пароль.

Сканируются только выбранные источники из разрешённого перечня. Ограничение
источника, rate limits и доступность сообщений Telegram остаются в силе. Если
Telegram Web не показывает группу аккаунту, сборщик не пытается обходить это
ограничение. Внутренний JavaScript API Web K недокументирован и может измениться.
